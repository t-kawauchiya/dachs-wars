# new-issue

決め事は docs/workflow.md の「Issue」と「タイトル」の節にある。先に読む。

## 手順

1. 何をしたいのかをオーナーから聞く。1つのプルリクで閉じられない大きさなら、分け方を提案する。
2. 作業に関係する設計の文書を読む。どの文書を読むかは AGENTS.md の「読む文書」の表で決める。完了条件は、その文書のルールに合わせて書く。
3. `.github/ISSUE_TEMPLATE/task.yml` を読み、`body` の各項目の `label` を、その順に `### <label>` の見出しにする。見出しを自分で作らない。フォームが変わっても、フォームから作った Issue と同じ形になるようにするため。
4. タイトルを「タイトル」の節の形で書く。
5. タイトルと本文の下書きをオーナーに見せる。了承を得てから、本文をファイルに書いて次を実行する。

   ```sh
   gh issue create --title "<タイトル>" --body-file <本文のファイル>
   ```

6. 作られた Issue の URL をオーナーに伝える。作業を始めるときは `/start-issue <番号>` を使うと伝える。
