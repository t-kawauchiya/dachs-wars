# open-pr

決め事は docs/workflow.md の「手元で検証」「プルリク」「タイトル」「レビュー」の節にある。先に読む。

## 手順

1. main の上にいないことを確かめる。ブランチ名から Issue 番号を読み取り、`gh issue view <番号>` で Issue を読み直す。
2. 「手元で検証」の節のチェックを全部回す。1つでも失敗したら、プルリクを作らずに直す。

   ```sh
   pnpm check
   pnpm typecheck
   pnpm test
   pnpm build
   ```

   画面が関わる作業で、まだ `pnpm dev` で動かしていなければ、動かして確かめる。

3. 変わったファイルを一覧にし、Issue の範囲に収まっているかを確かめる。

   ```sh
   git fetch origin
   git diff --stat origin/main...HEAD
   ```

   範囲外のファイルが1つでもあれば、プルリクを作らずに、そのファイルをオーナーに知らせる。

4. タイトルを決める。最初は Issue のタイトルを使う。ただし作業の途中で中身が変わっていれば、今の中身に合うように直す。タイトルは squash したときの main のコミットのタイトルになるため。
5. 本文を `.github/pull_request_template.md` の見出しで書く。テンプレートを読み、見出しを自分で作らない。説明のコメント（`<!-- -->`）は書かない。
   - 検証: 2と3で実際に確かめたことだけを書く。確かめていないことは書かない
   - 振り返り: 決め事の作業（`/architect`、レビュー）を省いたときは、省いたことをそのまま書く
   - 最後の行に `Closes #<番号>` を書く
6. push して、プルリクを作る。

   ```sh
   git push -u origin <ブランチ名>
   gh pr create --title "<タイトル>" --body-file <本文のファイル>
   ```

7. CI が終わるまで待ち、結果を確かめる。赤なら原因を調べて直す。

   ```sh
   gh pr checks <プルリクの番号> --watch
   ```

8. 「レビュー」の節の表と3の一覧から、使うコマンドを決めてオーナーに伝える。そのコマンドでレビューを始める。
