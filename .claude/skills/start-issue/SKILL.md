# start-issue

決め事は docs/workflow.md の「ブランチ」と「設計」の節にある。先に読む。

## 手順

1. Issue を読む。

   ```sh
   gh issue view <番号>
   ```

   閉じている Issue なら、作業を始めずにオーナーに知らせる。

2. 作業中の変更がないことを確かめる（`git status --short` が空）。変更があれば、どうするかをオーナーに聞く。
3. main を最新にしてから、ブランチを切る。名前は「ブランチ」の節の形にする。種類は Issue のタイトルの種類と同じにし、内容は英語の短い語をハイフンでつなぐ。

   ```sh
   git switch main
   git pull --ff-only
   git switch -c <種類>/<番号>-<内容>
   ```

   前のプルリクの変更が必要な作業で、そのプルリクがまだマージされていなければ、ブランチを切らずにオーナーに知らせる。

4. Issue の目的、完了条件、変えてはいけないことを、自分の言葉で短く言い直してオーナーに見せる。完了条件が確かめられる形になっていなければ、直し方を提案する。
5. 「設計」の節に従い、関係する設計の文書を読んでから `/architect with checkpoint` で計画を出すと伝える。
